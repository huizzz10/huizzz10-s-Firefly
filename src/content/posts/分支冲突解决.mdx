# 🚀 完整操作步骤

## 第一步：克隆你的仓库到本地

如果你还没有在电脑上操作过，首先需要把你的仓库克隆下来。  
例如  

```bash
git clone https://github.com/huizzz10/Firefly.git
cd Firefly
```

## 第二步：添加原项目作为上游仓库

把原项目 (`CuteLeaf/Firefly`) 添加为一个名为 `upstream` 的远程仓库，方便你随时拉取它的更新。

```bash
git remote add upstream https://github.com/CuteLeaf/Firefly.git
```

执行后，可以通过以下命令确认添加成功：

```bash
git remote -v
```

如果之前已添加过，此步可跳过。

## 第三步：拉取并合并原项目的最新代码

这是最关键的步骤，由于存在冲突，Git 无法自动合并，需要你手动处理。

### 3.1 拉取原项目的更新

```bash
git fetch upstream
```

### 3.2 切换到你的主分支

```bash
git checkout master
```

### 3.3 尝试合并原项目的 `master` 分支

```bash
git merge upstream/master
```

这时，Git 会提示你：**“自动合并失败，有冲突”**。

## 第四步：解决冲突

### 4.1 查看冲突文件

运行以下命令，它会列出所有存在冲突的文件：

```bash
git status
```

### 4.2 手动编辑解决冲突

用代码编辑器打开任意一个冲突文件，你会看到类似下面的标记：

```
<<<<<<< HEAD
这里是你自己修改的代码（你的 43 个提交）
=======
这里是原项目更新的代码（上游的 27 个提交）
>>>>>>> upstream/master
```

**你需要做的**：
- 阅读并分析两边的代码差异
- 决定最终要保留哪些内容
- 删除 `<<<<<<<`、`=======`、`>>>>>>>` 这些标记
- 将代码修改成你想要的最终样子

### 4.3 标记冲突为已解决

每解决完所有文件，告诉 Git：

```bash
git add .
```

### 4.4 完成合并

所有冲突都解决并标记好后，完成这次合并提交：

```bash
git commit --m "解决冲突"
```

Git 可能会自动打开一个文本编辑器让你编辑合并信息，直接保存退出即可。

### 第五步：将更新推送回 GitHub

现在你的本地仓库已经是最新且没有冲突的状态了。最后一步，将它推送到你 GitHub 上的远程仓库：

```bash
git push 
```

这里就结束了
